# Fallback Contributions

This directory is the safe fallback workspace for the Daily Autonomous GitHub Contributor workflow.

It is used only when a suitable upstream open-source contribution cannot be responsibly completed because no appropriate issue exists, repository access/fork permissions are insufficient, or the proposed change cannot be properly validated.

## Rules

- Prefer real upstream issues, maintainer-requested work, documentation gaps, tests, examples, integrations, or small tooling fixes first.
- Never create low-value commits solely to increase contribution activity.
- Keep fallback changes useful, independently reviewable, and testable where applicable.
- Record why fallback was used and what validation was performed.
- Never store credentials, tokens, private data, or restricted third-party material here.
- Never claim tests passed unless they were actually run or CI confirms them.
- Never accept CLAs, DCOs, legal attestations, security disclosures, or make personal representations on the owner's behalf.

## Good fallback work

Examples include tests, documentation, examples, input validation, CI reliability improvements, repository-quality checks, analysis tooling, and small maintainability improvements to this project.
